# Medarot-P

人気ゲームシリーズ「メダロット」を模したコマンドバトルRPGプロジェクト

---

## 0. 用語体系（4層）

本プロジェクトでは、意味の衝突（玉突きによる混同）を避けるため、概念を **Command / Action / Skill / Proficiency** の4層に分離しています。

Command（何をする指示） → Action（どう動く: 撃つ/殴る） → Skill（何の技: ライフル/ミサイル） → Proficiency（どれだけ熟練しているか）

|レイヤー|概念|日本語|責務|代表的な識別子|
|---|---|---|---|---|
|1|**Command**|指示|プレイヤーやAIが選ぶ実行予約（どのパーツを使う・スキップする）|`BattleCommand`, `PartCommand`, `CommandExecutor`|
|2|**Action**|行動形式|動作フォーム・リスク/リターン・時間補正（撃つ・殴る・我武者羅・支援）|`ActionType`, `ActionCategory`, `ActionDefinition`|
|3|**Skill**|技・能力|パーツ固有の技、命中方式、効果解決（ライフル・ミサイル・サンダー・ブロック）|`SkillType`, `SkillDefinition`, `SkillPresentation`|
|4|**Proficiency**|熟練度|メダルの各行動に対する適性値|`MedalData.proficiency`|

## 1. ゲーム仕様とコアメカニクス

### 1-1. コマンド選択と意思決定フロー

本ゲームでは、**「コマンダーの意志（使用パーツ選択）」** と **「メダルの性格（ターゲット選定）」** が明確に分離された2段階の意思決定フローを採用しています。プレイヤーおよびエネミーAIは全く同一のルールフレームワークに従って行動します。

|レイヤー|責務|担当|
|---|---|---|
|**コマンダーの戦術（Tactics）**|戦況に応じて「どのパーツ（行動）を選択するか」を判断|プレイヤー入力 / 思考AI|
|**メダルの性格（Personality）**|「どの敵機・どの部位を狙うか」の執念・照準を自動選定|メダルデータ駆動ロジック|

### 1-2. ターゲット解決タイミングの仕様（確定前提）

行動の種類によって、ターゲットが自動解決されるタイミングとルールが異なります。

1. **直接攻撃（射撃・格闘）**: **「行動形式（Action）」が選定タイミングを決定**

   * **射撃（撃つ・狙い撃ち）**: **充填開始時に事前ターゲット（予約固定）**。充填中にターゲット機体が機能停止、または対象部位が破壊された場合は「ターゲット喪失」による割り込み中断が発生します。
   * **格闘（殴る・我武者羅）**: **実行直前にターゲット解決（動的選定）**。中央ライン到達時に「最も前線にいる敵機」の生存部位を性格に従って即時決定するため、充填中のターゲット喪失は発生しません。
2. **特殊行動（妨害・支援・救護・防護・設置など）**: **「技（Skill）」が選定タイミングを決定**

   * 行動ごとの個別技（`SkillDefinition`）が選定タイミング（事前予約 / 直前選定 / 不要）およびルール（敵単体、最前線、味方最少HP、自身対象など）を定義・支配します。
   * 例：`サンダー` や `リペア` は事前予約、`スタン` は直前選定、`スキャン` や `プロテクト` は自身対象のため選定不要。

### 1-3. 変則ATB（Active Time Battle）と割り込み

* **往復型ライン進行**: 自陣（`0.0`）から中央の実行ライン（`1.0`）へチャージ（充填）し、技を実行後、自陣へ向けてクールダウン（放熱）します。
* **割り込み（Interrupt）**: 充填中に予約パーツが破壊された場合、あるいは予約ターゲットを喪失した場合、アクションは失敗となり、その場から即時自陣への後退（放熱）を開始します。
* **停止（STOP）状態**: スタン・サンダー等のデバフ効果時間中は、ゲージ進行およびコマンド実行が完全に一時停止します。
